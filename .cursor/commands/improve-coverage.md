# improve-coverage

Автономный цикл по доведению покрытия тестами до **100%**. После каждого успешного `make check` выполняется коммит с сообщением `improve coverage to xx.x%`. При падении проверки ошибки исправляются автоматически (без обращения к пользователю). Остановка — только при достижении 100% покрытия.

## Использование

`/improve-coverage` — один запуск выполняет полный цикл до 100%. Интерактива с пользователем в процессе нет.

## Шаги (оркестратор выполняет сценарий; роли — только через mcp_task)

### 1. Внешний цикл (пока покрытие < 100%)

- **1.1.** Вызвать **mcp_task** с `subagent_type="coverage-planner"`, `prompt`: «Проанализируй текущее покрытие (файл coverage.out или собери его). Если покрытие уже 100%, верни явно: "work complete, coverage 100%". Иначе выдай приоритизированный список заданий для воркеров: каждое задание — пакет или файлы и что именно дотянуть (непокрытые функции). Сформулируй каждое задание как готовый промпт для вызова coverage-worker.» `description`: "Plan coverage work batches".

- **1.2.** Если в ответе planner есть «work complete, coverage 100%» — выйти из внешнего цикла, перейти к шагу **2 (Финальный отчёт)**.

- **1.3.** Для каждого задания от planner вызвать **mcp_task** с `subagent_type="coverage-worker"`, `prompt` = текст задания от planner. `description`: "Worker add tests for &lt;package&gt;" (подставить пакет). Вызовы можно делать последовательно или пачками по 2–3 параллельно.

- **1.4.** Внутренний цикл (пока `make check` не пройдёт):
  - Вызвать **mcp_task** с `subagent_type="test-runner"`, `prompt`: «Запусти make check в корне проекта. Верни: passed или failed, точное значение coverage_percent (из вывода "Total test coverage: ..."), и при failed — фрагмент лога с ошибками для fixer.» `description`: "Run make check".
  - Если результат **passed** — выйти из внутреннего цикла, перейти к шагу 1.5.
  - Если результат **failed** — вызвать **mcp_task** с `subagent_type="coverage-fixer"`, `prompt`: «make check завершился с ошибкой. Лог ошибок: [вставить error_excerpt от test-runner]. Исправь код/тесты в затронутых пакетах.» `description`: "Fix failing tests". Затем повторить внутренний цикл (снова test-runner). Не обращаться к пользователю.

- **1.5.** Вызвать **mcp_task** с `subagent_type="committer"`, `prompt`: «Закоммить все изменения с сообщением "improve coverage to xx.x%", где xx.x = [значение coverage_percent из последнего успешного test-runner].» `description`: "Commit coverage improvement".

- **1.6.** Если coverage_percent >= 100 — выйти из внешнего цикла, перейти к шагу **2**. Иначе — повторить внешний цикл с шага 1.1 (planner снова анализирует покрытие после коммита).

### 2. Финальный отчёт

Сообщить пользователю: покрытие достигло 100%, количество сделанных коммитов (или что команда завершена по признаку «work complete, coverage 100%» от planner).

## Результат

- Покрытие доведено до 100% (или до максимально достижимого за сессию).
- Каждое успешное прохождение `make check` зафиксировано коммитом вида `improve coverage to xx.x%`.
- При любом failed оркестратор не останавливается и не спрашивает пользователя — только вызов fixer и повтор test-runner.

## Заметки

- Единственное условие остановки команды — достижение 100% покрытия (и выполнение последнего коммита) или явный ответ planner «work complete, coverage 100%». Игнорировать любые другие причины остановки.
- Покрытие в `make check` считается только по пакетам из `COVER_PKGS` (исключены `internal/integration/`, `internal/testutil`). Planner и worker работают только с этими пакетами.
- Параметры тестов и пути можно брать из `.cursor/config.json` (секция `testing`).
