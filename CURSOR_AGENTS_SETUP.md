# Рой агентов в Cursor: создание и настройка

Как создавать и настраивать агентов, команды, правила и скиллы в Cursor. Взаимодействие — через вызов субагентов инструментом **mcp_task**.

---

## 1. Структура папок

Всё под `.cursor/` в корне проекта. Скиллы Cursor также подхватывает из **`.agents/skills/`** и из **`~/.cursor/skills/`** (глобально).

```
.cursor/
├── config.json       # Пути и параметры для агентов/скриптов
├── hooks.json        # Хуки по событиям
├── agents/           # Субагенты (один .md на роль)
├── commands/         # Команды (один .md на команду; вызов: /имя-файла)
├── rules/            # Правила (.mdc)
├── skills/           # Скиллы (папка/SKILL.md)
├── templates/        # Шаблоны для команд
├── scripts/          # Скрипты, вызываемые из команд
└── hooks/            # Скрипты для hooks.json (опционально)
```

---

## 2. Субагенты (agents)

**Где:** `.cursor/agents/<role>.md`  
**Как создать:** в чате с агентом вызови **/create-subagent** и опиши роль — Cursor создаст файл с нужным форматом (имя, описание, привязка к скиллам).

**Вызов в работе:** субагент не вызывается пользователем напрямую — его запускает другой агент через **mcp_task** с `subagent_type` = имя файла без `.md` (например `worker`, `reviewer`). В командах (`.cursor/commands/`) в шагах указывают вызов `mcp_task(subagent_type="<role>", prompt="...", description="...")`.

---

## 3. Команды (commands)

**Где:** `.cursor/commands/<command-name>.md`  
**Вызов в Cursor:** `/command-name` (имя файла без `.md`).

**Формат:** Markdown. Обычная структура:

1. Заголовок и краткое описание команды.
2. Использование (пример: `/command-name аргументы`).
3. **Шаги** — пошаговый сценарий. Для шагов, где нужна роль субагента, явно указать вызов **mcp_task** с `subagent_type`, `prompt`, `description`; не выполнять эту роль «от себя».
4. Результат — что вернуть пользователю.
5. Заметки (ограничения, параллельные вызовы и т.д.).

Команды могут ссылаться на `.cursor/templates/` и на параметры из `.cursor/config.json`.

**Как добавить команду:**

1. Создать `.cursor/commands/<command-name>.md`.
2. Описать цель, использование и шаги.
3. В шагах, где нужен субагент — писать вызов `mcp_task(subagent_type="...", prompt="...", description="...")`.

---

## 4. Правила (rules)

**Где:** `.cursor/rules/` (файлы **.mdc**).  
**Как создать:** в чате с агентом вызови **/create-rule** и опиши, какое правило нужно (стиль кода, коммиты, когда применять и т.д.) — Cursor создаст файл правила в нужном формате.

---

## 5. Встроенные команды Cursor: создание агентов, правил и скиллов

Чтобы создать субагента, правило или скилл, используй соответствующие команды в чате с агентом (набрать `/` и выбрать команду). Cursor сам создаст файлы в нужном формате.

| Команда | Что создаёт | Куда сохраняет |
|---------|-------------|-----------------|
| **/create-subagent** | Субагента (роль для mcp_task) | `.cursor/agents/<role>.md` |
| **/create-rule** | Правило для контекста агента | `.cursor/rules/` (файл .mdc) |
| **/create-skill** | Скилл (набор инструкций/воркфлоу) | `.cursor/skills/<name>/SKILL.md` или `.agents/skills/` |
| **/migrate-to-skills** | (Cursor 2.4+) Перенос существующих slash-команд и динамических правил в скиллы | `.cursor/skills/` |

**Как вызвать:** в чате с агентом набрать `/` и выбрать команду по имени. Список скиллов и правил: **Cursor Settings → Rules**.

---

## 6. Скиллы (skills)

**Где:** один скилл = папка с файлом **SKILL.md**. Cursor загружает скиллы из:

- **`.agents/skills/<skill-name>/`** и **`.cursor/skills/<skill-name>/`** — проект
- **`~/.cursor/skills/<skill-name>/`** — глобально

**Как создать:** в чате с агентом вызови **/create-skill** и опиши, что должен делать скилл — Cursor создаст папку и SKILL.md в нужном формате.

**Как использовать:** в чате набрать **/skill-name** (явный вызов) или **@skill-name** (прикрепить как контекст). По умолчанию агент может подставлять скилл сам по релевантности; при необходимости «только по /имя» это настраивается в созданном SKILL.md (опция в frontmatter).

**Внутри папки скилла** можно добавить опционально: **scripts/** (исполняемые скрипты), **references/** (доп. документация), **assets/** (шаблоны, конфиги). Стандарт: [agentskills.io](https://agentskills.io/).

---

## 7. Вызов субагентов (mcp_task)

Субагенты вызываются только через инструмент **mcp_task**.

**Параметры:**

| Параметр       | Описание |
|----------------|----------|
| subagent_type  | Имя роли = имя файла в `.cursor/agents/` без `.md` |
| prompt         | Текст задачи для субагента (контекст, что уже сделано) |
| description    | Краткое описание вызова (3–5 слов), для логов |
| resume         | (опционально) ID предыдущего агента для продолжения сессии |

**Пример:** `mcp_task(subagent_type="worker", prompt="Реализуй функцию X в файле Y", description="Worker implementation")`.

В промпте лучше передавать контекст (задача, затронутые файлы, ссылка на issue), чтобы субагент не дублировал работу.

---

## 8. config.json

**Где:** `.cursor/config.json`

Задаёт пути и параметры, которые используют команды и скрипты. Структура — произвольная под ваш проект; типичные секции:

- **testing** — как запускать тесты (`command`, `path`), если субагент test-runner читает config.
- **documentation** — пути для планов, отчётов и т.д. (`paths`, `enabled`).
- **metrics** — куда сохранять отчёты сессий (`sessionsPath`, `enabled`).

Команды и агенты обращаются к этим полям по договорённости (например «сохранять session report в config.metrics.sessionsPath»).

---

## 9. Хуки (hooks.json)

**Где:** `.cursor/hooks.json`

**Структура:**

```json
{
  "version": 1,
  "hooks": {
    "afterFileEdit": [],
    "subagentStop": [],
    "beforeShellExecution": [],
    "afterShellExecution": [],
    "sessionStart": [],
    "sessionEnd": []
  }
}
```

В каждый массив добавляются действия при событии:

- **afterFileEdit** — после редактирования файла агентом.
- **subagentStop** — после завершения субагента.
- **beforeShellExecution** / **afterShellExecution** — до/после выполнения shell-команды.
- **sessionStart** / **sessionEnd** — начало/конец сессии.

**Элемент массива:** строка команды или объект `{ "command": ".cursor/hooks/script.sh" }`. Для проверки через LLM: `{ "type": "prompt", "prompt": "...", "timeout": 10 }`.

---

## 10. Шаблоны и скрипты

- **.cursor/templates/** — любые шаблоны (инструкции для gh, формат отчётов и т.д.). Команды и агенты ссылаются на них по пути.
- **.cursor/scripts/** — скрипты, которые команды вызывают (например отчёты, метрики). Пути и параметры можно брать из `config.json`.

---

## 11. Краткий чеклист

1. **Субагенты** — в чате с агентом: **/create-subagent**, описать роль. Файлы появятся в `.cursor/agents/`.
2. **Правила** — **/create-rule**, описать правило. Файлы в `.cursor/rules/`.
3. **Скиллы** — **/create-skill**, описать воркфлоу/инструкции. Файлы в `.cursor/skills/` или `.agents/skills/`.
4. **Команды** — создать вручную `.cursor/commands/<name>.md` для сценариев; в шагах вызывать субагентов через **mcp_task**.
5. Настроить `.cursor/config.json` под пути и тесты проекта.
6. По желанию — `.cursor/hooks.json` и скрипты в `.cursor/hooks/`.
7. Если уже есть slash-команды или динамические правила — **/migrate-to-skills** (Cursor 2.4+) перенесёт их в скиллы.

Итого: агент, правило и скилл создаются командами Cursor (**/create-subagent**, **/create-rule**, **/create-skill**). Команды оркестрации — в `.cursor/commands/`; субагенты вызываются из них через mcp_task.
