# Ежедневный маршрут Linglow

Дата: 2026-10-18. Статус: все семь режимов реализованы, финальная локальная проверка завершена; вход с главной подключён за включённым по умолчанию флагом. Итог и воспроизводимые проверки: `docs/DAILY_JOURNEY_QA_RU.md`.

## Цель и принятые решения

Заменить блок быстрых переходов «Твой путь сегодня» на главной полноценным ежедневным прохождением: экран маршрута с остановками и привычные экраны упражнений, понятный прогресс и анимация перемещения Lumi между заданиями. Выбор длительности в минутах не нужен.

Решения пользователя:

- Обязательные этапы: слова, чтение текста.
- Затем до трёх случайных разных режимов из пяти: описание картинки, диалог с ИИ, грамматика, тренировка форм глаголов, тренировка грамматики.
- Из случайных этапов разрешено пропустить один.
- Проверять и статус пользователя, и открытый контент. Если доступных режимов меньше трёх, упражнений будет меньше.
- Диалог выбирать среди открытых, но ещё не пройденных.
- Ошибки разбирать сразу; отдельного повторения ошибок в конце нет.
- Задания открываются на обычных экранах соответствующих режимов, без дорожки/шапки маршрута. После завершения — возвращение на маршрут и переход Lumi к следующей остановке.
- Дейлик — отдельное прохождение с сохранением места. Занятия вне дейлика сами по себе его не закрывают; ответы внутри обновляют обычный учебный прогресс.
- Грамматика: следующий блок теории и вопросы по нему; если все главы категории пройдены, а тест категории ещё нет — тест категории. SRS-грамматика остаётся отдельным режимом.
- Если к повторению меньше 20 слов, перед тренировкой дать задание добавить 10–15 новых слов из словарных наборов.

Дополнительные проверенные факты:

- `GrammarChapterView.handleQuizAnswer` проверяет inline-вопросы на клиенте, в этом пути нет записи завершения блока. `GetContinueChapter` возвращает главу, а не позицию внутри неё. Для «следующего блока» потребуется серверный учёт.
- `GrammarChaptersView` предлагает тест категории, когда у всех глав `passed=true`. Нельзя подменить это условие просмотром теории.
- `WordSetStudyView` различает «знаю» и «добавить в изучение» (`study/know`, `study/learn`); добавление карточек реализует `WordSetService`. Одному слову могут соответствовать несколько карточек и направлений. Порог 20 слов нельзя считать по числу карточек.

## 1. Пользовательский сценарий

### Главная

Вместо строк быстрых переходов — карточка «Маршрут дня»: Lumi с картой, миниатюра пути с остановками, текущий этап и одна основная кнопка. Состояния: «Начать», «Продолжить — остановка 3 из 5», «Маршрут пройден». Завершённый дейлик показывает фактический результат; повторный клик не создаёт новое прохождение того же дня.

Использовать существующий адрес `/city/daily-route` как экран прохождения. Ссылки с главной и из города ведут в одну сессию. Самостоятельные разделы обучения сохраняют свои сценарии.

### Внутри маршрута

Пример, а не фиксированный набор случайных режимов:

```text
Слова                  Чтение          Грамматика        Картинка         Диалог
[набор → тренировка] → [текст + quiz] → [теория + quiz] → [описание]      → [NPC] → Итог
       ✓                   ✓                Lumi             ○                ○
```

- Максимум пять основных остановок: две обязательные и до трёх случайных. Добавление слов — подэтап первой остановки, поэтому основной маршрут не меняет длину.
- Дорожка находится только на экране маршрута. После задания пользователь возвращается сюда: Lumi перемещается к следующей остановке, показаны её цель и кнопка «Открыть задание». При обычном выходе из упражнения текущая остановка остаётся незавершённой; кнопка меняется на «Продолжить задание».
- Кнопка текущей остановки открывает существующий экран упражнения сразу с выбранным содержимым и явным контекстом дейлика. Каталог не подменяет назначенное задание. Шапку/дорожку маршрута на экране упражнения не показывать. Подэтап добора открывает обычные экраны наборов и изучения слов, сохраняя контекст при смене набора.
- Прогресс остановок отображается на маршруте; внутренний прогресс задания — на существующем экране режима. Для диалога показывать задачи сценария, не выдуманный процент до ответа ИИ.
- Путь линейный. Можно посмотреть названия следующих остановок; запустить можно текущую. Выход сохраняет место.
- На экране маршрута у случайных остановок кнопка «Пропустить этап», рядом «Остался 1 пропуск». Пропуск необратим в этом прохождении, не заменяет режим новым случайным и не даёт учебного зачёта. Слова и чтение пользовательским пропуском не закрываются.
- Итог: что выполнено, сколько слов добавлено/повторено, какой текст прочитан, результаты остальных заданий. Пропущенный этап отмечен отдельно. Нет обязательного повторения ошибок и дополнительных заданий после финиша.

### Анимации

- Путь — адаптивный SVG на отдельном экране маршрута; остановки и карточки — обычные доступные HTML-элементы. На телефоне дорожка адаптируется к ширине. Учебные экраны используют собственную привычную шапку без карты маршрута.
- После ответа: спокойное появление разбора; после остановки: отметка результата, заполнение участка пути, перемещение Lumi и смена позы. На финише — поза clapping/cup и короткое свечение остановок.
- Ориентир длительности: 150–250 мс для ответа/карточки, 400–700 мс для перемещения. Не задерживать чтение объяснения таймером и не скрывать его автоматически.
- Использовать существующие изображения `LgLumi`, Vue transitions и CSS `transform/opacity`, без новой библиотеки и генерации графики в первой версии.
- `prefers-reduced-motion`: мгновенное перемещение и простая смена состояния. Фокус переводить на заголовок задания; результат объявлять через `aria-live`. Звук и вибрация подчиняются существующим настройкам.
- Иконки только Lucide, имя только Lumi, без emoji.

## 2. Состав и подбор заданий

Сервер составляет и сохраняет маршрут при первом явном старте. Просмотр главной ничего не создаёт. Перезагрузка и повторный старт возвращают тот же состав.

1. Определить пользователя, курс, текущий день и существующее прохождение.
2. Собрать обязательные этапы и доступные кандидаты пяти дополнительных режимов.
3. Выбрать до трёх **разных режимов** равновероятно, без возвращения; затем выбрать конкретное доступное содержимое каждого. Большой каталог одного режима не повышает вероятность его выбора.
4. Зафиксировать порядок, идентификаторы контента, версию правил и лимиты заданий. Дополнительные режимы идут после слов и чтения, в сохранённом случайном порядке.
5. Если доступно 0–2 режима, сохранить более короткий маршрут. Не добавлять закрытые задания, дубли режима или рекламу подписки вместо задания.

| Режим | Доступность и выбор | Объём и завершение |
|---|---|---|
| Слова | Текущий курс, готовые карточки и штатная очередь; порог считать по уникальным словам | Предложение: до 20 разных доступных слов, штатные форматы ответа и обновление SRS. Выполнение очереди, независимо от точности |
| Чтение | Открытый уровень по общей mastery, опубликованный доступный текст; сначала непрочитанный | Один текст и его штатная проверка понимания. Завершённая попытка закрывает остановку; отметка «прочитан» — только по обычным правилам |
| Описание картинки | `TierAllowsFeature(..., "picture_description")`, открытый район, опубликованный квест с изображением и задачами | Один квест; предпочтительно непройденный. Конец штатной попытки, разбор результата |
| Диалог | `conversation`, открытый район, выполненные prerequisites, прошедший cooldown, `quest_passed=false` | Один доступный NPC-квест. Достижение обязательных целей либо штатный конец попытки по лимиту; простое закрытие чата не завершает этап |
| Грамматика | Доступные категории/главы и сохранённое продвижение по блокам; при готовности непройденного теста категории выбрать его | Один следующий блок теории с привязанными вопросами либо полноценный тест категории. Тестовые пороги и правила открытия не менять |
| Формы глаголов | Испанский курс, `spanish_verb_forms_enabled`, открытые scopes, непустая готовая очередь | Предложение: до 10 карточек через текущую практику v2; без её дополнительного повтора ошибок |
| SRS-грамматика | `GetGrammarTrainingAvailability`, доступные главы и реальная непустая очередь после фильтрации | До 20 вопросов из доступных разных блоков, как в обычном режиме; штатная проверка и обновление памяти |

Доступ проверяется на сервере при подборе, запуске остановки и записи действия. Использовать текущие проверки статуса пользователя и предметные правила; нельзя брать только клиентский `locked` или проверять лишь CEFR. Для районов — `BuildCourseMastery`, для грамматики — правила доступа grammar service, для глаголов — `getUserVerbScopes`. Подбор кандидатов не должен запускать тренировки, менять SRS, создавать чат или обращаться к ИИ.

### Слова: сначала набор, затем практика

- Сохранить число уникальных слов к повторению на момент старта первой остановки. Если оно меньше 20, открыть обычный выбор доступных словарных наборов с сохранённым контекстом дейлика и показать цель «Добавить N новых слов».
- Предлагаемая формула цели: `N = min(15, max(10, 20 - due_words))`. Это выбор реализации в пределах пользовательского диапазона: при 0 слов — 15 новых, при 19 — 10 новых. Цель фиксируется один раз.
- Считать только новые уникальные добавления в изучение через этот подэтап. «Знаю», уже изучаемое слово и повтор запроса не увеличивают счётчик. Можно сменить набор, сохранив счётчик.
- После достижения цели автоматически открыть подготовленную тренировку. Добавление 15 слов при пустой очереди не обязано дать 20 разных слов: провести доступную короткую тренировку и не запускать второй круг добора.
- Новые слова должны участвовать в этой тренировке, а не оставаться за пределами неё из-за обычного лимита новых карточек. Для дейлика явно ограничить общий размер и включить выбранные новые слова; не менять глобальные настройки обычных тренировок.
- Выбирать готовый контент. Если выбранное слово требует подготовки карточек, сохранить добавление и показать ожидание/повтор; разрешить перейти к другой готовой позиции без потери добавленного слова и без двойного зачёта. Ошибка подготовки не должна выглядеть как успешная тренировка.

### Грамматика: теория и тесты

- Получить текущую доступную непройденную главу с учётом `GetContinueChapter` и учебного порядка. Для неё хранить завершённые блоки; выбирать первый незавершённый блок теории и связанные с ним inline-вопросы.
- Если все главы категории имеют штатный `passed`, а тест категории не пройден, предложить его до продвижения к следующей категории. Наличие неуспешной попытки не означает «тест пройден».
- Добавить серверную проверку/сохранение ответов inline-вопросов, сейчас этот путь клиентский. Связи вопроса с блоком брать из банка; не угадывать по тексту или позиции.
- Завершение блока не выдаёт `chapter.passed`. Для перехода от изученных блоков к обычному прохождению главы нужен её штатный тест. Предложение для этого промежуточного состояния: подтип остановки «грамматика — тест главы» после всех блоков; пользователь явно не выбирал этот подтип, он отмечен ниже как уточнение проекта решения.
- Существующий тест категории проводить полностью, без сокращённого теста с ложным официальным зачётом. Показывать его реальный объём до начала.

## 3. Завершение, пропуск и восстановление

- Отдельные показатели: `resolved_steps` (выполненные, пропущенные, недоступные) и `completed_steps` (выполненные). На дорожке виден пройденный путь; итог честно показывает «4 выполнено, 1 пропущен», а не «5 выполнено».
- Не более одного пользовательского пропуска среди выбранных дополнительных режимов, даже если их меньше трёх. Сервер блокирует второй пропуск и пропуск обязательного этапа.
- Ошибка в ответе не блокирует завершение очереди. Неверные ответы сохраняются неверными; дейлик не повышает результат, не открывает район и не ставит `quest_passed` за само участие.
- Для текста, теста, картинки и NPC адаптер различает `attempt_finished` и учебный `passed`. Для NPC/картинки штатное исчерпание попытки даёт результат «попробовал, цель не достигнута»; обычный выход только приостанавливает.
- После каждого принятого ответа сохранять позицию и разбор. После перезагрузки восстанавливать тот же вопрос или уже полученный разбор; не просить заново отправлять принятый ответ. На обычном экране режима черновик неотправленного текста хранить локально в области пользователя/курса/прохождения.
- Не засчитывать действия из других разделов как шаги дейлика. При изменении общего прогресса извне перепроверять пригодность будущего контента; не забирать и не сбрасывать самостоятельную сессию.
- Если во время прохождения исчезло право или контент, объяснить причину и вывести этап из маршрута как `unavailable`, сохранив прошлые ответы. Это не расходует пользовательский пропуск и не выдаёт учебный успех. Не перемешивать остальные остановки.
- Сбой сети/ИИ — повторяемая ошибка, а не отсутствие контента: сохранять место и введённый ответ, предлагать повтор. Не завершать дейлик автоматически при 5xx.
- Завершение дейлика — один серверный переход и одно событие, независимо от числа вкладок или повторов запроса. Обычные результаты не начисляются повторно за финиш.

## 4. Серверная модель и API

Новые названия ниже — проект контракта, существующие контракты перечислены выше.

### Данные

Аддитивная миграция с ближайшим свободным номером при реализации:

- `daily_journeys`: `id`, `user_course_id`, `journey_date`, `day_timezone`, `status`, `algorithm_version`, `revision`, `started_at`, `completed_at`, `updated_at`; уникальность `(user_course_id, journey_date)`.
- `daily_journey_steps`: `id`, `journey_id`, `position`, `mode`, `required`, `status`, `content_ref_json`, `content_version`, `target_count`, `state_json`, `result_json`, `skipped_at`, `completed_at`; уникальная позиция внутри маршрута. В state — подэтап, очередь идентификаторов, курсор, принятый разбор и ссылки на предметные попытки.
- `daily_journey_actions`: `journey_id`, `client_action_id`, `step_id`, `action_type`, `payload_hash`, `status`, `result_json`; уникальный ключ действия для восстановления ответа после сетевого сбоя. Повтор ключа с другим payload отклоняется.
- Для продвижения по теории: `grammar_block_progress` по `user_course_id`, главе, блоку и версии контента с датой завершения. Не использовать SRS-memory как замену факта изучения блока. Устаревание контента обрабатывать отдельно от исчезновения блока.

`daily_journeys.status`: `active`, `completed`, `archived`, `unavailable` (нет ни одного выполнимого задания). `daily_journey_steps.status`: `pending`, `active`, `completed`, `skipped`, `unavailable`. UI-разбор хранится внутри активного этапа, а не трактуется как новая попытка.

Состояние предметных очередей дейлика хранить отдельно от глобальной активной тренировки слов/глаголов. Общие библиотеки проверки ответа и обновления прогресса переиспользовать через явный контекст сессии. Нельзя вызывать текущий `StartSession` и тем самым завершать самостоятельное занятие.

### Предлагаемый HTTP-контракт

| Метод и адрес | Назначение |
|---|---|
| `GET /api/linglow/daily-journey?course_code=...` | Компактное состояние текущего дня и доступность продолжения; без создания сессии и генерации заданий |
| `POST /api/linglow/daily-journeys` | Создать или вернуть маршрут текущего дня для курса |
| `GET /api/linglow/daily-journeys/{id}` | Получить сохранённый маршрут и текущую остановку; разбор восстанавливается на обычном экране упражнения |
| `POST /api/linglow/daily-journeys/{id}/steps/{step_id}/actions` | Действия `start`, `add_word`, `answer`, `message`, `ack_feedback`, `skip`; типизированные payload для режима |

Запрос действия содержит `client_action_id`, `expected_revision`, `action`, `payload`. Ответ — revision, прогресс и разрешённый `launch` (`routeName`/`params`) текущего задания. Разбор отображается на обычном экране режима; приватное состояние очереди и правильные ответы не включаются в ответ маршрута. Повтор принятого действия восстанавливает его сохранённую квитанцию; при конфликте последующего действия клиент перечитывает актуальное состояние. `409` возвращает указание перечитать состояние; `403` не маскируется под сетевой сбой. Сервер проверяет владельца, курс, текущий этап, допустимость действия и ссылку на выбранный контент. Клиент не может сообщить «этап завершён» или произвольное число выполненных заданий.

Для обычных ответов сохранять предметный результат, SRS/event, позицию дейлика и квитанцию действия в одной транзакции. Где текущий сервис не принимает транзакционный интерфейс, выделить небольшой общий метод, сохранив обычные обработчики. Не собирать завершение из двух независимых HTTP-запросов «ответить» и «отметить этап».

Для ИИ-вызовов: короткой транзакцией резервировать действие, затем вызвать провайдера вне блокировки БД, после — атомарно применить результат и предметные события. Повтор восстанавливает сохранённый результат или состояние `processing`. После падения между ответом провайдера и сохранением возможен повтор внешнего запроса; гарантировать отсутствие двойного локального зачёта, а не обещать exactly-once у провайдера.

## 5. Фронтенд: привычные экраны и явный контекст дейлика

Уточнение пользователя от 2026-10-18 отменяет первоначальное решение о встроенных упражнениях. Новую вёрстку вопросов/ответов и `DailyJourneyStepHost` не создавать.

- `DashboardView.vue`: карточка `DailyJourneyCard`; компактный `daily_journey` в overview и инвалидация после подтверждённых действий. До готовности всех режимов главный вход не переключать.
- `CityDailyRouteView.vue`: только маршрут, цель текущей остановки, открыть/продолжить, один skip, переходы и итог. Дорожка не появляется на учебных страницах.
- `api/dailyJourneyClient.ts`, `useDailyJourney.ts`: серверное состояние, revision, сохранённый client_action_id для retry, защита от смены пользователя/курса.
- `useDailyJourneyContext.ts`: разобрать `journey_id`, `journey_step_id`, `course_code` в URL; проверить их через API. URL не является разрешением и не может содержать доверенные результаты/очередь. Сервер связывает контекст с владельцем, курсом, текущим шагом и конкретной предметной попыткой.
- Кнопка остановки сначала подтверждает `start` на сервере, затем открывает существующий route конкретного упражнения с контекстом. Ответ start содержит только разрешённый route/params, без произвольного внешнего URL.
- `TrainingView.vue`: тот же UI карточки; при дейлике отдельный источник сессии и действий. Не вызывать обычный `StartSession`/`GetActiveSession`. Завершение очереди возвращает на маршрут после разбора последнего ответа.
- `WordSetsView`/`WordSetStudyView`: обычные экраны наборов/карточек; контекст сохраняется при смене набора. `learn` внутри дейлика атомарно обновляет уникальный счётчик; `know` не выполняет цель.
- `ReadingTextView.vue`/`ReadingPassageBlock.vue`: тот же текст и quiz. Различать завершение попытки и успешную отметку прочитанного. По подтверждённому завершению и после разбора вернуться на маршрут.
- `GrammarChapterView.vue`/`GrammarTestView.vue`/`GrammarTrainingView.vue`: существующая теория/вопросы/тест; дейлик ограничивает назначенный блок или полную предметную попытку и сохраняет ответы на сервере.
- `PlaceChatView.vue`/`PictureQuestChatView.vue`: те же экраны, задачи, исправления и жалобы; предметная сессия привязана к дейлику. Закрытие чата не завершает остановку.
- `VerbFormsTrainingPanel.vue`: тот же UI с явным источником сессии/действий; без запуска самостоятельной практики и повторного круга ошибок внутри дейлика.
- Возврат из упражнения без завершения ведёт на тот же маршрут; перезагрузка страницы восстанавливает отдельную предметную сессию. Прямой вход с неверным/чужим контекстом показывает ошибку, а не запускает обычную тренировку как fallback.
- Самостоятельные экраны без journey-контекста сохраняют текущий сценарий. Переиспользуются экраны и предметные функции, не создаются копии страниц или новый движок SRS.

## 6. Этапы реализации

1. **Макет маршрута и состояния.** Карточка главной, маршрут, пропуск, восстановление и итог на фикстурах; открытие существующих экранов с явным контекстом, без собственной вёрстки заданий; мобильный и desktop-вариант, reduced motion. Результат — проверяемый экран будущего режима.
2. **Состояние и подбор на сервере.** Миграция, репозиторий `daily_journey_repository.go`, сервис `daily_journey_service.go`, адаптеры доступности, случайный выбор и API в `internal/web/daily_journey.go`. Сначала тестируем фиксированный состав и восстановление без нового UI в production.
3. **Обязательные остановки.** Наборы → слова → чтение на существующих экранах, отдельные предметные сессии и атомарные записи. Проверить отсутствие конфликтов с обычной тренировкой и отсутствие двойных результатов.
4. **Грамматика.** Учёт блоков, теория с вопросами, выбор теста категории и SRS-очередь; связка с обычным учебным прогрессом.
5. **Остальные случайные режимы.** Глаголы v2, описание картинки и NPC-диалог с реальными guards, завершением попытки и восстановлением сообщений.
6. **Финальная интеграция.** Подключить главную/overview, анимации, локализации, крайние случаи, проверки доступности и аналитические события. Только после поддержки всех пяти дополнительных режимов выпускать замену главного блока.

Каждый этап — небольшой проверяемый набор изменений. Номера миграций и точные извлечённые helper-файлы выбрать по состоянию репозитория в момент начала работы. Не создавать отдельный движок SRS и не пересобирать банки контента ради маршрута.

## 7. Проверки и критерии приёмки

### Сервер

- Два обязательных этапа, 0–3 разных дополнительных; каждый из пяти может попасть в выборку, без дубликатов режимов. Детерминированный RNG в тестах.
- Матрица free/pro/pro_plus × EN/ES × открытый/закрытый контент; грамматические prerequisites, cooldown NPC, `quest_passed`, scopes глаголов.
- Порог слов: 0, 5, 19, 20, 21 уникальное слово; несколько карточек одного слова не увеличивают число слов; «знаю» не выполняет добавление; повторы learn идемпотентны.
- Грамматика: следующий блок; все главы пройдены + тест категории не пройден; неуспешная попытка теста; отсутствие вопросов; изменение версии контента. Изучение блока не выдаёт passed главы.
- Один skip, запрет второго и обязательного; пропуск при 1–2 доступных дополнительных режимах; недоступность этапа не тратит skip.
- Повтор старта, одновременные вкладки, повтор действия, тот же ключ с другим ответом, падение после commit, рестарт процесса, потеря сети во время ответа ИИ.
- Обычная тренировка не закрывает дейлик; дейлик не сбрасывает её. Смена курса и чужие идентификаторы не дают доступа к сессии.
- Точный единичный прирост предметной статистики и SRS; ошибки не становятся правильными. Финиш не дублирует предметные события.

### Интерфейс

- Задания открываются на существующих экранах без шапки пути; завершение и обычный выход возвращают на маршрут с различным состоянием. Неверный контекст не запускает самостоятельную тренировку.
- Полный маршрут из 5 этапов; маршрут с добором слов; короткий маршрут; пропуск; окончание с ошибками; продолжение после перезагрузки на вопросе и на разборе.
- Карточка главной отражает серверный прогресс; общий путь и прогресс текущего задания не противоречат друг другу.
- Отсутствие текста/набора/прав, ошибка ИИ, retry после сети, изменение доступа между остановками.
- Мобильный экран 360–390 px и desktop; клавиатура, фокус, reduced motion, выключенные звук/вибрация, отсутствие emoji.
- Регрессии обычных слов, чтения, грамматики, глаголов, NPC и картинки после извлечения компонентов.

## 8. Выпуск и совместимость

- Аддитивная миграция автоматическая; исторические дейлики не создавать из агрегатов, поскольку старое выполнение ссылок не было отдельным прохождением.
- Старый `GET /api/linglow/daily-route` сохраняется для старых клиентов и текущих потребителей; новое поле `daily_journey` добавляется в overview отдельно. Главная новой версии переключается на него.
- Флаг `LINGLOW_DAILY_JOURNEY_ENABLED` позволяет скрыть новый вход и вернуть прежний главный блок без удаления сохранённого прогресса. Откат флага не отменяет уже сделанные учебные действия.
- Проверить наличие миграции перед включением UI, новый образ, публичную версию, прохождение на тестовом пользователе обоих курсов. Production `kubectl` выполняет оператор на сервере; локально его не запускать.
- Импорт учебного контента не нужен, если реализация не меняет банки. При обнаружении недостающих материалов оформить их отдельно с обычным выпуском/импортом.
- События: старт, завершение остановки, пропуск, недоступность, завершение маршрута; метрики — завершение среди начавших, выходы по остановкам, доля технически недоступных заданий. Ответы и тексты диалогов в новую аналитику не копировать.

## 9. Проектные предложения, не отдельные решения пользователя

Эти детали записаны явно для проверки при реализации; они не изменяют согласованный основной сценарий.

1. **Нет подходящего текста.** Пользователь уточнил fallback только для слов. Предлагается повтор доступного прочитанного текста; если нет ни одного доступного — явно исключить остановку без ложного зачёта. Не выдавать это за уже согласованное правило.
2. **Недостаточно новых слов в открытых наборах.** Предлагается уменьшить цель до доступного количества и потренировать имеющиеся слова; если нет даже готовой тренировки — состояние «контент недоступен», без успешного завершения пустого дейлика. Повторить ранее выученные слова автоматически пользователь не просил.
3. **Последний блок изучен, но глава не пройдена.** Предлагается штатный тест главы как следующий подтип грамматического этапа. Иначе дейлик не может сам довести главу до `passed` и подготовить тест категории. Не засчитывать главу за чтение теории.
4. **Размеры.** До 20 разных слов, 10 форм глаголов и до 20 SRS-вопросов — текущие параметры; без настройки минут. Формула добора 10–15 — предложение в заданных пользователем пределах.
5. **Граница дня.** Первая версия использует календарный день сервера, как текущий daily-route; сохраняет зону в маршруте. Начатое до полуночи не обнуляется: можно закончить прежний маршрут или явно начать сегодняшний, архивировав прежний. Завершение прежнего не засчитывается за два дня. Персональная настройка зоны — вне этого изменения.
6. **Offline.** Первая версия создаёт и подтверждает дейлик онлайн. При потере связи сохраняются последний подтверждённый шаг и локальный черновик; полное офлайн-прохождение смешанного маршрута не обещается. Существующие самостоятельные offline-режимы работают по прежним правилам.

Главные риски: смешение разных типов сессий, двойная запись результатов при повторах, отсутствие серверного прогресса блоков теории и различие между «закончил попытку» и «успешно освоил». Они закрываются этапами 2–5 и отдельными проверками, а не анимацией интерфейса.

Старый активный маршрут сохраняется через полночь; явный старт нового дня архивирует прежний.
- `daily_journey_service.go`: равновероятный выбор до трёх разных дополнительных режимов, формула добора слов, запрет обязательного/повторного skip, повторная проверка доступа и контракт предметных адаптеров. Отсутствие контента отличается от временной ошибки.

Одного включения флага недостаточно: `Ready()` требует семь реальных предметных адаптеров. Зарегистрированы все семь реальных адаптеров: слова, чтение, грамматика, SRS-грамматика, глаголы, картинка и NPC. GET сообщает `enabled=true` при готовности всех адаптеров; явное значение `false` выключает новый вход и запуск. Нет фикстурного fallback в production.

При выключенном флаге используется прежний экран; главная использует новую карточку только при серверном `enabled=true`.

Законченная неудачная попытка закрывает остановку без отметки «прочитано»; успешное чтение требует >50%. Используются ReadingTextView/ReadingPassageBlock, явное продолжение разбора и восстановление после reload.
- Источник упражнений и фасад слов подключают обычные экраны к отдельной сессии. Явный контекст запрещает fallback в самостоятельную тренировку. Проверки доступа и предметные записи работают в одной транзакции без второго соединения из пула.

- Грамматика: подбор через штатный `GetContinueChapter` с учётом placement; первый незавершённый блок и связанные inline-вопросы, затем полный тест главы. Полный тест категории предлагается только при штатном `passed` всех опубликованных глав и отсутствии пройденного теста категории. Изученный блок сохраняется отдельно по user/course/content version и не даёт `chapter.passed`.
- `GrammarChapterView` и `GrammarTestView` используют сохранённый источник дейлика: серверная проверка, явное продолжение inline-разбора, сохранение ответов полного теста по одному без самостоятельного submit, восстановление итогового разбора и возврат после подтверждения. Полный тест сохраняет штатный порог >=50%; исправлена прежняя ошибка первой записи chapter progress ровно на 50%.
- SRS-грамматика: отдельная очередь до пяти вопросов из разрешённых глав/placement и опубликованного контента. Приоритет просроченных блоков внутри доступного пула; подбор не создаёт memory rows. На `GrammarTrainingView` сохраняются вопрос/разбор, отключён автоматический переход для дейлика. Память, grammar_attempts, exercise_attempts, learning_events, дневная статистика и включённое каноническое SRS-зеркало записываются вместе с курсором/квитанцией.
- Reorder на обычном `GrammarQuestion` умеет получать перемешиваемые слова и пунктуацию без готового ответа. Сервер не раскрывает correct/accepted answers, объяснения и подсказки вариантов до проверки; штатный источник вопросов сохраняет прежнее поведение.

- Формы глаголов: сохранённая очередь до 10 готовых v4-карточек с правилами штатного `GetPracticeQueue`, лимитом новых карточек и фильтром явного курса. Подбор не создаёт user_verb_cards; выбранные карточки материализуются при старте атомарно. Отдельная очередь в шаге дейлика не создаёт/не завершает verb_training_sessions, review events имеют `session_id=NULL`.
- `VerbScopeAllowed`, `GradeVerbPractice`, `PublicVerbPractice` и `UnlockedVerbScopes` общие для штатной тренировки и дейлика: unlock-gates требуют пройденной главы, legacy-настройки не открывают времена. Подсказка сохраняет assisted до показа правила/таблицы форм; правильный ответ с помощью не увеличивает mastery. SRS, verb_review_events, exercise_attempts, learning_events и дневная статистика записываются в общей транзакции с действием/курсором.
- Обычные `VerbTrainingView`/`VerbFormsTrainingPanel` работают через отдельный источник дейлика, без автоматического повторения ошибок после финиша и без fallback в глобальную сессию при сетевой ошибке. Сохранённые вопрос/подсказка/разбор восстанавливаются; черновик ввода scoped по пользователю, курсу, прохождению, остановке и карточке. Формы для подсказки приходят из подтверждённого exercise API; кликабельные слова получают явный курс.

- ИИ-инфраструктура: миграция `000083_daily_journey_ai_reservations.sql`, статусы processing/retryable/completed, один processing на маршрут, приватный снимок входа и срок резервирования. `ReserveAI` фиксирует действие без зачёта, `RunAI` работает вне транзакции, `CompleteAI` атомарно сохраняет предметные записи/курсор/квитанцию; старый token не может применить поздний ответ после истечения срока или нового запуска.
- `DailyJourneyAIAdapter` разделяет PrepareAI/RunAI/ApplyAI. Ошибка провайдера или записи освобождает резервирование для повтора того же ключа/входа; завершённая квитанция возвращается без нового вызова. Доступ повторно проверяется после ИИ. Истёкший запрос не блокирует маршрут навсегда; активный не допускает skip/переход/архивацию новым днём. Ошибки processing (503 + Retry-After), провайдера (502) и утраты резервирования (409) отделены; приватный вход/token не возвращаются клиенту.
- Картинка/NPC: реальные опубликованные квесты, тариф, открытый район/уровень, prerequisites/cooldown/непройденность NPC; картинки предпочитают непройденные. Приватный снимок включает задачи и критерии, публичный API их не раскрывает. Поддержаны split- и legacy-промпты NPC; сетевой вызов выполняется вне транзакции.
- Миграция `000084_daily_journey_chat_sessions.sql`: отдельные предметные сессии, привязанные к остановке. Обычный вход/возобновление не подхватывает их. Сообщения, исправления, цели, события и статистика записываются вместе с результатом ИИ и квитанцией. Пропуск закрывает привязанную сессию без зачёта.
- Обязательные цели дают штатный успешный зачёт; полное выполнение чеклиста учитывается отдельно. Лимит ходов/токенов завершает попытку без успешного зачёта, если обязательные цели не достигнуты. Остановка завершается только после подтверждения итогового разбора; обычный выход приостанавливает её.
- Обычные `PictureQuestChatView`/`PlaceChatView` подключены через `useDailyJourneyChat`, без шапки пути и fallback в самостоятельный чат. Сообщения/цели восстанавливаются с сервера; scoped-черновик сохраняется при ошибке и reload. Повтор использует прежний ключ/текст, подтверждённые сообщения не дублируются. Явный курс используется без смены глобального курса.
- Эта инфраструктура проверена на тестовом провайдере и реальном PostgreSQL. Живой smoke EN/ES × picture/NPC через Polza и `openai/gpt-4.1-mini` прошёл на синтетических заданиях; локальная `.env` не менялась.

- Dashboard overview включает `daily_journey` с минимальным состоянием: ID/курс/дата/статус/revision и названия/статусы остановок. Предметный контент, ответы, launch и разборы в этот кэш не копируются. Главная показывает согласованную `DailyJourneyCard` только при серверном флаге и совпадении курса; при выключенном флаге или пропущенной секции остаётся прежний вход. Карточка локализована RU/EN/ES, переход продолжает сохранённый маршрут.
- Подтверждённые start/action/retry инвалидируют overview через `daily-journey-progressed`. Read-only загрузка не инвалидирует кэш; поздний ответ после смены scope не отправляет событие. Проверены переключение флага, смена курса, отсутствие секции и переход с точным journey/course.
- Миграция `000085_daily_journey_events.sql`: серверные lifecycle-события старта, завершения/пропуска/недоступности остановки и завершения/недоступности маршрута. Записываются вместе с результатом в одной транзакции; уникальные ключи исключают дубли при повторе. События содержат только ссылки, тип, revision и время; ответы/диалоги не копируются. PostgreSQL-тест подтверждает откат событий вместе с транзакцией, восемь повторов без дублей, начальную недоступность, пропуск и завершение маршрута; целевые repository/web-тесты прошли с race detector. Прямые события ухода с экрана пока не добавлены: незавершённые остановки позволяют анализировать отсев, но не причину выхода.
