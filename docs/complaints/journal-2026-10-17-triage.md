## Дополнение: ручная замена озвучки chat

По отдельному запросу пользователя локально синтезировано `chat` голосом Piper `es_ES_davefx_medium` (испанский Испании). MP3: `logs/complaints/audio-20261017/chat-es.mp3`, 3870 байт, длительность 0.664399 с. Через существующий `POST /api/internal/tts/audio` с `target_lang=es`, `provider=manual`, `engine=piper` файл установлен на production. API вернул `ready`, `manual:piper`, `/media/tts/es_ru/31/e0/chat.mp3`, updated_at `2026-10-17T07:03:36.269964Z`. Ответ и проверка: `logs/complaints/audio-20261017/chat-upload-verification.json`.

Файл перечитан с production по URL с новым query-параметром; SHA-256 совпадает с локальным: `45698f6721509fe6e9f46d8743399833ded16e2a3e7b1f92af45ec54fa18daea`. Испанская запись установлена в origin. Старые клиенты могут удерживать прежний ответ: media route задаёт `Cache-Control: public, max-age=31536000, immutable`, а прежняя загрузка перезаписывала `chat.mp3`.

Исправлен `StoreExternalAudio`: новые загрузки сохраняются под именем с SHA-256 содержимого; после успешной записи DB pointer переключается на новый путь. Старый ready-файл не перезаписывается. Повторная загрузка одинаковых байтов сохраняет URL; новая запись получает другой URL и обходит старый immutable cache. Это изменение включено в подготовленный релиз `0.12.214`. #45 остаётся открытой до проверки клиентского воспроизведения после выпуска; статус `pending` из первоначального прогона для этой записи уже не актуален.
