# План улучшения тренировки спряжений

Статус: реализовано локально, выпуск не выполнялся. Дата: 2026-09-08.

Фактический результат: новый API `/api/verb-training/v2/`, сохранение сессии/разбора в существующих JSON-колонках БД, короткие сессии, серверный учёт помощи и повтор ошибок без повышения SRS. Миграция `000078_verb_practice_indexes.sql` добавляет только индексы. Банк не перегенерирован: исправлено его использование и три привязки глав; [результаты аудита](VERB_TRAINING_CONTENT_AUDIT_RU.md).

Принятые решения: placement и ручная настройка времён не заменяют прохождение главы; базовое ядро — 24 глагола; частотный список — 898 глаголов/AUX. Для регулярного правила три успешных самостоятельных ответа на разных леммах закрывают добавление новых однотипных карточек до следующей ошибки/помощи. Отложенные повторения уже изучаемых форм сохраняются.

Дальнейшие разделы сохраняют согласованный объём и критерии реализации.

Цель: пользователь понимает, какую форму нужно образовать, отвечает без раскрытого решения и получает короткий разбор. Сохраняем отдельную очередь повторений и переход от выбора к вводу. Кнопки букв с ударениями не добавляем.

## Учебная цель и отбор контента

Уточнение пользователя: тренировка закрепляет правила окончаний по временам и лицам по мере прохождения грамматики. Изучение всех глаголов не является целью.

| Решение | Реализация |
|---|---|
| Открытие времён | Presente доступно изначально; остальные времена добавляются после освоения соответствующего материала курса. Ранее изученные остаются на повторении. Источник — фактический прогресс, а не просто право открыть главу |
| Базовое ядро | Небольшой явно заданный список частых неправильных глаголов и регулярных образцов -ar/-er/-ir доступен без добавления в личный словарь. Не создавать за пользователя карточки обычной словарной тренировки |
| Личный словарь | Остальные глаголы подключаются из словаря пользователя; новые отбираются по частотности и потребности в отработке конкретного правила |
| Регулярные формы | Покрывать времена, лица и модели окончаний на разных глаголах, не превращать каждую новую лемму в обязательный полный цикл заучивания |
| Неправильные формы | Отдельно закреплять частые исключения и повторяющиеся изменения основы. Классификация зависит от времени/формы: глагол не считается одинаково неправильным во всех временах |
| Состав сессии | Ошибки и назначенные повторения, практика нового времени и поддержание предыдущих; гарантировать место регулярным образцам и не допускать вытеснения их частыми исключениями |

Первым шагом реализации становится сопоставление завершённых разделов/блоков курса с каноническими ключами времён. Согласовать семантику placement и старой ручной настройки отдельно: доступ к главе не равен освоению материала. Фильтр разрешённых времён применять к уже созданным карточкам, upcoming, текущей очереди и повтору ошибок, а не только при создании карточек.

### Результат предварительного аудита контента

В локальном `courses/spanish-grammar/training_pack/verb_forms/lemmas` найдено 363 глагола, по 96 карточек (16 scopes × 6 лиц), всего 34 848. Все 100 лемм из `Freq100VerbLemmas` присутствуют. Это подтверждает структурное наличие, но не полную лингвистическую корректность банка.

Выборочно проверенные presente-карточки ser, ir, tener, hacer, hablar, comer имеют осмысленные примеры, перевод и реальные варианты. Runtime upsert при этом может перезаписывать импортированные карточки результатом упрощённой генерации. До генерации нового контента исправить приоритет источников и запретить замену проверенного примера fallback-текстом.

| Контентная работа | Объём |
|---|---|
| Сохранить и проверить | Словарь форм и существующие JSON; начать с базового ядра и частотных неправильных глаголов |
| Добавить | Идентификаторы правил и групп исключений по времени/лицу, краткие объяснения и подсказки, учебный приоритет и частотный ранг |
| Исправить адресно | Ошибочные/неестественные примеры, неверные переводы, неоднозначные варианты и пропуски покрытия в приоритетном наборе |
| Не генерировать массово | Не переписывать 34 848 карточек и не расширять число глаголов ради размера банка |

Перед адресной генерацией получить отчёт: глагол × каноническое время × лицо × правило × качество примера/перевода/вариантов. Согласовать ключи scopes: в артефактах встречается `es.preterito_indefinido.indicativo`, а runtime-словарь использует `es.pretérito.indicativo`. Открытие времени должно проверяться сквозным тестом от прогресса курса до выдачи карточки.

Для регулярных форм добавить агрегированную оценку освоения правила по ответам на разных леммах; для частых исключений сохранять индивидуальное повторение формы. Не засчитывать один выученный глагол как доказательство освоения всех окончаний. Схему групп правил и взаимодействие этого показателя с существующим SRS определить до изменения очереди и включить в миграционный план.

## Целевой сценарий

1. Открытие тренировки запускает короткую сессию до 10 карточек без дополнительного обязательного экрана настроек.
2. Вверху — «2 из 10», шкала прогресса и название времени/наклонения.
3. В карточке — `barrer — подметать`, предложение `Vosotros ___ el suelo cada mañana`, варианты или поле ввода.
4. «Подсказка» раскрывает короткое правило; «Все формы» открывает справочник текущего глагола. Использование помощи явно обозначается.
5. После ответа всегда видны правильная форма и заполненное предложение. После ошибки — короткое объяснение различия. Переход только кнопкой «Дальше».
6. «Не знаю» показывает решение без негативной эмоциональной фразы; форма остаётся требующей повторения.
7. Итог разделяет самостоятельные ответы, ответы с помощью, ошибки и «Не знаю»; предлагает следующую порцию или повтор ошибок.

### 1. Контракт задания и ответа

В `internal/web/verb_forms.go` ввести явные структуры ответа вместо передачи всего сохранённого `prompt` клиенту.

| Ответ API | Предлагаемые поля |
|---|---|
| `start` / `current` | Идентификаторы сессии и карточки, прогресс, `input_mode`, `options`, `question`, `lemma`, `gloss`, `mood`, `tense`, `person`, `number`, доступность помощи |
| Получение помощи | Короткое правило для текущей карточки и отметка использования помощи; форму можно раскрыть только явным действием пользователя |
| `answer` | `outcome` (`correct`, `incorrect`, `unknown`), `assisted`, выбранный ответ, правильная форма, заполненное предложение, перевод, объяснение, наличие следующей карточки и итог |

- До ответа не возвращать отдельные `expected_form`, решение в `example_translation` или готовое предложение. В choice правильная форма, естественно, остаётся среди вариантов без указания, что она правильная.
- Идентификатор ответа/карточки проверять сервером; повторная отправка после сетевого сбоя не должна повторно менять SRS или продвигать очередь. Обновление SRS, события и позиции сессии согласовать атомарно.
- Клиентские состояния: загрузка → задание → отправка → разбор → следующая карточка/итог. Ошибки сети показывать с повтором действия, введённый ответ сохранять.
- При выходе или обновлении страницы восстанавливать текущую карточку либо последний разбор, если сессия существует. После потери серверной сессии показывать понятное предложение начать новую; не обещать восстановление после рестарта сервера без отдельного хранения состояния.
- Новый API и интерфейс выпускать согласованно: определить поведение уже открытой старой вкладки (обновление приложения/совместимый переход), чтобы она не пропускала разбор автоматически.

### 2. Варианты, примеры и объяснения

- Загружать формы одного глагола из `verb_forms_dict` пакетно; генератор вариантов получает набор реальных форм вместо одного `surfaceForm` и `lemma`.
- Основные неверные варианты — другие лица того же времени. Формы других времён использовать только при явно указанном целевом времени и однозначном задании.
- Удалять дубли и все допустимые правильные варианты из набора неверных. Учитывать совпадающие формы разных лиц и альтернативные формы спряжения.
- Если четырёх уникальных вариантов нет, показывать 2–3. Не дополнять выдуманными словами; при невозможности выбора использовать ввод с понятной инструкцией.
- Заменить универсальные фразы «так, естественно» на контексты, совместимые со значением глагола. Использовать существующий каталог шаблонов и метаданные классов глаголов.
- Если естественный пример недоступен, честный запасной вариант: `Vosotros ___ (barrer)` с явно указанным временем. Не выдавать техническую русскую справку за перевод.
- Разделить полный перевод, значение инфинитива и грамматическое объяснение. Если перевода нет, не выдумывать его при показе карточки.
- Объяснения строить по проверенным правилам и метаданным: для регулярных форм можно выделять основу/окончание; для нерегулярных и составных форм не применять механическое разбиение.
- Сохранить строгую проверку ударений. При ответе, отличающемся только диакритикой, показывать конкретное различие и короткую обратную связь. Кнопок специальных букв нет.

### 3. Интерфейс и помощь

- Переработать `webapp/src/components/VerbFormsTrainingPanel.vue`; при необходимости вынести разбор и справочник в небольшие компоненты.
- Убрать длинный абзац перед вариантами; отдельно оформить инфинитив, значение и время. Уменьшить отступы без уменьшения удобных областей нажатия.
- На телефоне разместить «Дальше» в устойчивой нижней области, учитывающей нижнюю навигацию, safe area и клавиатуру. Прогресс не должен прыгать при появлении разбора.
- Заменить анонимную `i` на понятные действия «Подсказка» и «Все формы». В справочнике сначала показывать текущее время и шесть лиц, остальные времена раскрывать отдельно.
- Использование подсказки/таблицы отмечать на сервере для текущей попытки, в том числе при повторном открытии экрана. Правильный ответ с помощью не повышает освоение как самостоятельное воспроизведение; конкретное обновление SRS покрыть тестами.
- Локализовать интерфейс и грамматические подписи через `ru/en/es.json`; испанские предложения и формы остаются испанскими. Перевод и значение — на поддерживаемом языке обучения, независимо от языка интерфейса; отсутствие перевода обработать явно.
- Использовать существующие Lucide-иконки; корректный фокус, клавиатурную навигацию и текстовый статус ответа, не только цвет.
- Сетевые и пустые состояния писать для ученика: без названий импортёров, БД и конфигурации.

### 4. Сессии, итоги и повтор ошибок

- Ограничить стандартную порцию 10 карточками с учётом доступной очереди и текущего ограничения новых форм. Сохранить распределение глаголов и защиту от одинаковых соседних заданий.
- Итог: сколько выполнено, сколько самостоятельно верно, сколько с помощью, сколько ошибок/«Не знаю». Группировать затруднения по времени и лицу только на основании реальных ответов этой сессии.
- «Продолжить» запускает следующую доступную порцию; при отсутствии карточек показывать завершение и ближайшее повторение, если данные доступны.
- «Повторить ошибки» создаёт отдельный учебный проход по уникальным ошибочным/неизвестным формам завершённой сессии. Не обходит права пользователя и доступные ему формы.
- Этот немедленный проход не повышает SRS за запоминание только что показанного ответа и не переписывает исходную точность. Обычное отложенное повторение сохраняется.
- Расширить события попыток полями результата и помощи; итог и список ошибок читать с сервера. Для старых событий не угадывать, был ли неверный ответ пропуском: сохранять доступную историческую классификацию.

## Проверки и критерии готовности

| Проверка | Условие приёмки |
|---|---|
| До ответа | Нет готового предложения или отдельного правильного ответа; подсказка открывается только явно |
| Варианты | Реальные формы, уникальность, один допустимый ответ; наборы с совпадающими/альтернативными формами обработаны |
| Разбор | Правильная форма видна при выборе, вводе и «Не знаю»; переход только по «Дальше» |
| Надёжность | Двойной клик, сетевой повтор, уход со страницы, обновление, последняя карточка не дают двойной оценки или потери разбора |
| SRS | Самостоятельный ответ, помощь, ошибка, неизвестный ответ и немедленный повтор имеют проверенную семантику |
| Контент | Проверены регулярные, нерегулярные, возвратные, составные формы, subjuntivo и imperativo; примеры семантически подходят глаголу |
| UI | Ширины 360/390/430 px, открытая клавиатура, длинные формы, светлая/тёмная тема, все три языка интерфейса |
| Регрессии | Обычные тренировки слов, настройки доступных времён и существующая очередь работают как раньше |

Добавить целевые Go-тесты контрактов, генерации, оценки и репозитория; Vitest-тесты переходов карточки и восстановления после ошибок. Проверять существующие соседние тесты затронутых пакетов. После реализации: `go test ./internal/spanishverbs ./internal/service ./internal/repository ./internal/web`, `npm --prefix webapp run type-check`, целевые Vitest-тесты и `npm --prefix webapp run build`. Дополнительные обязательные проверки — по актуальным правилам проекта.

## Обновление данных и выпуск

1. Перед реализацией изменений данных сверить все писатели карточек: runtime upsert, JSON sync и API hydration. Старый импорт не должен возвращать раскрывающие ответ тексты и искусственные варианты.
2. Добавить версию генерации либо эквивалентный критерий устаревания. Подготовить dry-run обновления существующих карточек с количеством изменений и выборкой до/после.
3. Сохранить идентификаторы карточек, связи с пользователями и историю SRS. Не удалять и не пересоздавать прогресс ради нового текста.
4. Миграцию событий сделать аддитивной и совместимой со старым кодом. Старые строки читать без искусственно восстановленных данных.
5. Если меняются артефакты подмодуля курса, сначала проверить и выпустить курс, затем обновить указатель основного репозитория. Не запускать генерацию всего банка без необходимости.
6. Проверить синхронизацию в локальной тестовой БД и выпуск образа. Обновить runbook по фактическому пути и namespace Linglow.
7. Production-команды выполняет оператор на сервере. Локальный `kubectl` не использовать. Точные команды обновления данных оформить после определения механизма backfill.
8. После выпуска проверить существующую и новую карточку, choice/typed, помощь, ошибку, итог и повтор ошибок. Откат приложения не должен требовать удаления новых событий или потери прогресса.

Первый завершённый срез: этапы 1–3 с минимальным серверным учётом помощи. Затем короткие сессии и расширенный итог. Обновление данных и проверки выполняются для каждого выпускаемого среза, а не откладываются до конца.
