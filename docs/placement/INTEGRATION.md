# Доступ к курсу и совместимость диагностики

Реализовано 2026-09-03. Production не проверялся; локальные проверки используют PostgreSQL testcontainers.

## Граница данных

`grammar_placement_access.user_course_id` ссылается на конкретное обучение пользователя в `user_courses`. Английский и испанский не делят строку доступа. Новые сессии и результаты диагностики хранятся отдельно; поля `score` и `total_questions` в доступе описывают последнюю попытку, а список разделов — накопленное право открытия.

`GrammarAttemptRepository.ForCourse(courseCode)` создаёт независимое представление репозитория. Конструктор `GrammarService` выбирает код по `GrammarBundleID` и `NativeLang`: в существующей сборке альтернативный сервис меняет только `GrammarBundleID`, поэтому `TargetLang` здесь не подходит. Общий репозиторий в `bot.go` остаётся неизменным. Старые unscoped методы сохранены для архивного кода и чтения исторической таблицы; пользовательские grammar-сервисы работают через scoped экземпляры.

Для завершения новой диагностики:

```go
repository.SaveDiagnosticPlacementAccessTx(ctx, tx, userCourseID, score, total, openedSections)
```

Функция вызывается внутри той же транзакции, что и сохранение результата сессии. Самостоятельно учитывает старый доступ; предварительная запись или вызов `Get` не нужны. Атомарный `ON CONFLICT` объединяет старые и новые разделы и устраняет дубли. Низкий результат пересдачи не закрывает ранее доступные разделы. Откат транзакции откатывает и доступ.

## Наследие и происхождение

Старая `grammar_placement_test` не изменяется и остаётся архивом исходного результата. Когда новой строки нет, чтение проверяет старую строку и оставляет только идентификаторы пространства имён соответствующего языка: `en.grammar.` либо `es.grammar.`. При первом сохранении диагностики этот доступ переносится в рамках её транзакции. Чтение само по себе ничего не записывает и не записывает пользователя на другой курс.

- `source=legacy` означает исторический результат или вызов старого placement API через scoped репозиторий.
- `source=admin` означает явное ручное назначение.
- `source=diagnostic` означает последнее обновление новой диагностикой.
- `admin_override=true` сохраняется при пересдаче, если накопленный доступ включал ручное назначение. Исходная legacy-запись остаётся в архиве; источник последнего события не подменяет источник всей истории.

Пустая старая строка, результат только с неизвестными идентификаторами или идентификаторы без языка не дают достаточных данных для определения курса. Их нельзя автоматически присвоить обоим языкам. Строка остаётся в архиве; доступ из неё не выдумывается. Вопросы и результаты из одного курса никогда не используются для открытия другого.

Администратор может явно уменьшить уровень. Очистка (`level=""`) сохраняет пустую строку с `cleared=true`: чтение возвращает отсутствие результата, но fallback не воскрешает старую строку. Новая диагностика снимает этот признак, начиная с очищенного доступа. Явное назначение `below_a1` отличается от очистки: оно остаётся видимым ручным результатом с пустым списком открытий.

## Потребители

- Список разделов, доступ к главам и продолжение курса используют scoped `GrammarService.AttemptRepo`.
- `CourseRepository` при расчёте доступа на карте получает placement по коду курса, а не по одному `user_id`.
- Sentence composition worker читает placement через `ForCourse(courseCode)`.
- Список пользователей админки и ручное назначение уровня используют курс выбранного администратором языка, в том числе `?course_code=`. Ответ админки включает `course_code` и `source`.
- `GetGrammarStatistics` учитывает реальные `grammar_progress` и попытки. Открытые диагностикой или администратором главы не получают 100%, `passed` или подтверждённый учебный уровень автоматически. Средний балл фильтруется по главам языка.

Существующее правило разворачивания максимального открытого уровня на разделы того же курса сохранено для совместимости. Доступ к опубликованному разделу и фактическое освоение этого раздела остаются разными понятиями.

## Проверки

`grammar_placement_access_test.go` проверяет разделение EN/ES, сохранение исторического ручного доступа, слабую пересдачу, очистку без восстановления legacy, явный Below A1 и откат транзакции. `admin_placement_course_test.go` проверяет назначение A2 английскому и B2 испанскому одному пользователю, раздельное отображение и очистку, отсутствие фиктивного учебного прогресса. Обновлён прежний тест статистики, ожидавший 100% за одно открытие.

Команды:

```bash
go test ./internal/repository -run '^TestCoursePlacementAccess_' -count=1
go test ./internal/service -run '^(TestGrammarService_(GetGrammarStatistics|AdminSetGrammarPlacementLevel|GetContinueChapter|CanAccessChapter|CanAccessSection|IsSectionOpenedByPlacement)|TestGrammarAttemptRepository_SavePlacement_)' -count=1
go test ./internal/web -run '^(TestAdminPlacement_|TestHandleAdminUsers_)' -count=1
```

Для выпуска нужна миграция `000077_language_placement.sql` до первого обращения обновлённого приложения. Старые строки не удаляются; отдельный перенос production-БД для начала работы диагностики не требуется.

## Новый пользовательский экран

`/learning/placement-test` открывает `LanguagePlacementView.vue`. Старый `/learning/grammar/placement-test` перенаправляет туда. Приветствие не создаёт сессию: старт или восстановление происходит по нажатию кнопки. Язык берётся из `useCourse`, во все вызовы передаётся явный `course_code`.

Устройство хранит только idempotency key, идентификатор сессии и ещё не отправленный выбор в `linglow.placement.v1:<user_id>:<course_code>`. Вопросы и правильные ответы в этот черновик не записываются. При сетевом сбое остаётся текущая карточка; повторная отправка использует тот же идентификатор вопроса. После возвращения сервер восстанавливает сохранённые ответы, а локальный неподтверждённый выбор остаётся выбранным. Пустая строка — явное «Не знаю», отсутствие ключа — вопрос ещё не отвечен.

После 30 ответов основной блок закрывается на сервере; при пограничном результате экран показывает выданные сервером 6 уточнений и не позволяет вернуться к основным ответам. Результат запрашивается отдельной кнопкой. Профиль уровней, опубликованные рекомендации и разбор приходят с сервера; Vue выводит их текстовой интерполяцией. Повторный тест создаёт новый idempotency key. Ответ завершившегося запроса другого языка/пользователя не подменяет текущий экран.

UI переведён на RU/EN/ES, использует Lucide, radio inputs и явные состояния сохранения/сети. Компонентные тесты с API-заглушками покрывают отсутствие автоматического старта, безопасный вывод текста, восстановление сетевого черновика, изоляцию пользователей/курсов, переход 30→36, финал и пересдачу:

```bash
npm --prefix webapp run test -- src/views/languagePlacementView.test.ts
npm --prefix webapp run build
```
