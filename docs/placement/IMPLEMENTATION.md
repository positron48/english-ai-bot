# Самостоятельная диагностика EN/ES: реализация

2026-09-03. Реализована по разрешению пользователя. Пользователь разрешил commit/push и выпуск; импорт CLI после deployment выполняет сам. Итог публикации фиксируется в ответе задачи и истории Git.

## Что работает

- Отдельный экран `/app/learning/placement-test`, вход из грамматики и перенаправление старого маршрута. Приветствие, сохранение ответа, «Не знаю», возврат внутри открытого блока, продолжение после перезагрузки/сетевой ошибки, результат, разбор и пересдача. Интерфейс RU/EN/ES; вопросы EN→RU и ES→RU.
- По 400 самостоятельных вопросов, 40 умений, 80 вопросов каждого A1–C1. Контекст и инструкция не требуют чтения курса. Семейства объединяют узнаваемые ситуации; смена имени не считается новым заданием.
- Исходники находятся в **отдельных репозиториях** `courses/english-grammar/placement` и `courses/spanish-grammar/placement`. Готовые пакеты для runtime — `internal/placementbundle/{en,es}/bank.json`. Уровни и главы сверены с реальными машинными картами курсов; спорные границы и исключения объяснены в `EN_RESEARCH.md` и `ES_RESEARCH.md`.
- Каждый банк прошёл авторскую проверку и независимое агентское ревью всех 400 карточек. Исправления повторно просмотрены. Это внутреннее ревью; внешний лингвист и пользовательский пилот не подменяются агентами или валидатором.
- Тест содержит 30 вопросов: шесть каждого уровня, по два каждой редакционной сложности. При необходимости добавляются шесть уточнений одного уровня. Подбор предпочитает новые ситуации и разные умения, учитывает последние 12 попыток. Внутри попытки семейства не повторяются; при исчерпании банка сначала возвращаются наиболее давние показы.
- Результат — ориентировочная оценка грамматики в письменном контексте по сетке Linglow, с профилем по уровням и рекомендациями. Это не сертификат общего CEFR-уровня. Политика `editorial-v1` описана в `API.md`.
- Сессия закрепляет вопросы, ключи, объяснения, варианты, резерв и карту умений. Новая версия банка не меняет начатую попытку. Ключи и объяснения выдаются после завершения.
- Данные и доступ привязаны к `user_course_id`. Результат одной попытки и накопленный доступ разделены. Слабая пересдача не закрывает открытые разделы и не приписывает прохождение уроков. Админка, статистика и потребители доступа переведены на курсоспецифичное чтение.
- Ссылки результата учитывают текущую публикацию главы и раздела. UI ведёт прямо в доступный урок; закрытая последовательностью тема остаётся рекомендацией на будущее. Историческая оценка при изменении доступа не пересчитывается.
- API требует авторизации, проверяет владельца сессии, сохраняет ответы и результат на сервере. Старые API теста из глав возвращают 410; альтернативная офлайн-оценка удалена. Swagger обновлён.

## Распределение работы и ревью

- `spanish_bank`: ES исследование, 400 вопросов, авторская проверка; независимое ревью EN.
- `english_bank`: EN исследование, 400 вопросов, авторская проверка; независимое ревью ES.
- `placement_integration`: курсоспецифичный доступ, legacy/admin, фактический прогресс, интерфейс, Swagger, независимое ревью backend.
- `root`: общий контракт, схема/blueprint, сборка/валидация, сессии/оценка/API, интеграционные регрессии, исправления ревью и проверка реального интерфейса.

Внутренние content reviews завершены: `EN_INDEPENDENT_REVIEW.md`, `ES_INDEPENDENT_REVIEW.md`. `BACKEND_REVIEW.md` сохраняет исходные findings. Все пять исправлены:

| Сценарий | Исправление и регрессия |
|---|---|
| Одновременные finish/start | Общий порядок блокировок enrollment → session → access, завершённая попытка не превращается в abandoned; `TestPlacementConcurrentFinishAndStartKeepCompletedHistory` |
| Отзыв опубликованной главы/родительского раздела | Фильтр каждого ответа с result, включая историю и повтор finish; `TestPlacementPublishedLinksFollowCurrentParentState` |
| Нет нового active bank, но есть закреплённая попытка | Загрузка банка только после поиска существующей сессии; `TestPlacementResumeSurvivesBankOutageAndLostResponse` |
| Потерян ответ на resume с новым idempotency key | Все принятые ключи привязываются к исходной сессии, в том числе после finish; тот же тест |
| Неподдерживаемая версия политики | Явное 410 и возможность нового старта; `TestPlacementUnsupportedPolicyExpiresAndCanRestart` |

Browser QA дополнительно выявила переход к опубликованному, но закрытому уроку. Исправление проверяет фактический `CanAccessChapter`, сохраняя рекомендации и исторический балл; регрессия `TestPlacementResultLinksRespectCurrentCourseAccess`.

## Доставка

1. Сохранить контент отдельными коммитами в репозиториях EN/ES; затем обновить ссылки submodule и сохранить общие изменения в основном приложении. В коммиты выпуска входят только изменения диагностики; чужие изменения не включаются.
2. Перед сборкой выполнить `make placement-validate`; при редактуре банков — `make placement-bundle` и затем валидацию. Пересобрать приложение обычным процессом проекта.
3. Миграция `000077_language_placement.sql` создаёт банки, сессии, привязки ключей идемпотентности и курсоспецифичный доступ; старый `grammar_placement_test` сохраняется.
4. В текущем GitOps-манифесте Linglow задан `CONTENT_SOURCE=db`; автоматического импорта learning content среди initContainers нет. После успешного rollout оператор запускает **из нового image**: `kubectl -n linglow exec deploy/linglow -- /app/import_learning_content --course-code=all --commit`. Команда импортирует штатный learning content и новые диагностические банки. Для bundle-режима банки уже в бинарнике. Наличие файлов в image само по себе не обновляет DB-банк.
5. После выпуска оператор проверяет оба курса через приложение: старт, ответ, продолжение и результат. Production SQL/команды исполняются человеком по AGENTS.md; локальный kubectl не использовался.

Проверка активных DB-версий оператором (без пользовательских ответов):

```bash
kubectl -n english exec -it deploy/english-postgres -- psql -U english -d linglow_unified -c "SELECT course_code, version, active, jsonb_array_length(data_json->'items') AS questions FROM placement_banks WHERE active ORDER BY course_code;"
```
