Следующее исправление: [разнообразие заданий и подбор известных опорных глаголов](2026-09-19/diversity/README.md).

Актуальная схема и выбранная модель: [Gemini 3.8 Flash + low, сравнение и smoke от 2026-09-19](2026-09-19/model-comparison/README.md). [Первый этап исправления](2026-09-19/README.md) описывает общий пул и сохранение частичных наборов. Ниже — исторический отчёт от 2026-09-18; его требование полного набора заменено новой схемой.

Проверка и исправления от 2026-09-18. Режим: генерация набора из 20 предложений,
перевод ученика, исправления, пояснения и оценка star / passed / failed.

## Изменения

- Отдельная модель `AI_SENTENCE_MODEL`, по умолчанию
  `google/gemini-3-flash-preview`. Применяется к генерации, проверке качества
  заданий и оценке ответов; остальные AI-режимы сохраняют свою конфигурацию.
- Контекст испанского «вы» должен определять количество адресатов, вежливость,
  при необходимости регион и пол. Контекст артикля у объекта не определяет
  обращение и не объясняет артикль у подлежащего.
- Генератор и контроль качества проверяют все артикли, включая `al`/`del`.
  Контроль возвращает цитаты из показанного контекста для каждого выбора.
  Сервер проверяет наличие этих цитат и достаточное количество оснований.
  Это проверка структуры доказательств; лингвистическую достаточность фактов
  по-прежнему оценивает LLM, поэтому абсолютной гарантии качества нет.
- Вместо двух ответов «принять/отклонить» используется один подробный разбор
  с основаниями. Ошибка проверки не пропускает непроверенные задания.
  Если после ограниченного числа повторов нет полного набора, набор не создаётся.
- Проверяющая модель получает только русский текст, видимый контекст и ответ
  ученика. Эталон используется для бесплатной проверки совпадения, но не
  передаётся LLM как предполагаемый единственный правильный вариант.
- Пунктуация, регистр и пробелы не снижают оценку. Лексические ударения,
  апострофы внутри слов и дефисы сохраняются при сравнении.
- Каждая ошибка содержит исходный фрагмент, исправление и русское объяснение.
  Сервер сверяет покрытие всех изменений, исключает повторный подсчёт и
  формирует итоговое объяснение из тех же ошибок. Оценка определяется числом
  минимальных замен/вставок/удалений слов: 0 — star, 1 — passed, 2+ — failed.
- Спорные исправления артиклей/местоимений и добавление испанского подлежащего
  проходят дополнительную перепроверку. Максимум два запроса оценки на ответ.
  Некорректный JSON или несогласованные исправления после повторной проверки
  дают ошибку проверки, не записывая попытку ученика.

## Облачные результаты

Провайдер — Polza. Ключ читался из локального `.env`, в отчётах его нет.
Использованы синтетические примеры, а не данные учеников из production.

Исходная реализация с `gpt-4o-mini`: **10/24** проверок. В процессе сравнивались
`gpt-4o-mini`, `gpt-5.4-nano`, `gpt-5.4-mini`, `gpt-5.4`,
`claude-haiku-4.5`, `gemini-3-flash-preview`, а также nano/mini с reasoning low.
Одной замены модели оказалось недостаточно. На промежуточном промпте даже
GPT-5.4 ошибался в двух контекстных случаях (22/24).

Результат выбранной Gemini после исправления промптов и логики:

| Проверка | Результат | HTTP-вызовы | Вход / выход, токены | Списание Polza |
|---|---:|---:|---:|---:|
| Основные примеры ES/EN | 24/24 | 29 | 44 787 / 3 359 | 3,840351 ₽ |
| Дополнительные примеры с другой лексикой | 14/14 | 19 | 28 579 / 2 254 | 2,489803 ₽ |

Основной прогон занял 82 с, дополнительный — 57 с; генерация 20 ES — 80 с.
Это суммарное последовательное время сценариев, не SLA отдельного запроса.
Ориентир: **7–8 ₽ за генерацию 20 ES и проверку 20 ответов** при похожей доле
ошибок/перепроверок. Точное совпадение с эталоном не вызывает API. Стоимость
зависит от длины словаря, повторов генерации, ответов и маршрутизации провайдера.
Единицы `usage.cost` подтверждены [документацией Polza](https://polza.ai/docs/gaidy/chat-completions).

Это результат небольшой регрессионной выборки, а не гарантия отсутствия любых
лингвистических ошибок. Промпты дорабатывались по основным примерам; затем
проверялась отдельная выборка с другой лексикой. Её первоначальную формулировку
«О книге больше ничего не известно» уточнили до контекста только о столе,
чтобы сам тест не подразумевал неизвестную книгу. Два обнаруженных пограничных
случая привели к добавлению перепроверки. Сравнение исходного и конечного
результата включает изменения и модели, и кода, и промптов.

## Повторение

Локально, без оплачиваемых вызовов:

```sh
go test ./internal/ai ./internal/config -count=1
go test ./internal/service -run 'Test.*Sentence' -count=1
go test ./internal/bot ./internal/web -run '^$'
```

Платные smoke-тесты читают `POLZA_AI_API_KEY` из окружения или корневого `.env`.
Ключ не передаётся аргументом командной строки и не печатается.

```sh
RUN_SENTENCE_REGRESSION_LLM=1 \
SENTENCE_TEST_MODELS=google/gemini-3-flash-preview \
go test ./internal/ai -run '^TestSentenceRegressionLLM$' -v -count=1 -timeout 10m

RUN_SENTENCE_REGRESSION_LLM=1 SENTENCE_TEST_HOLDOUT=1 \
SENTENCE_TEST_MODELS=google/gemini-3-flash-preview \
go test ./internal/ai -run '^TestSentenceRegressionLLM$' -v -count=1 -timeout 10m

RUN_SENTENCE_GENERATION_LLM=1 SENTENCE_TEST_MODEL=google/gemini-3-flash-preview \
SENTENCE_TEST_OUTPUT_DIR=/tmp/sentence-eval \
go test ./internal/ai -run '^TestSentenceGenerationContextLLM$' -v -count=1 -timeout 15m
```

Для английского smoke: дополнительно `SENTENCE_TEST_COURSE=en_ru SENTENCE_TEST_COUNT=5`.
Генерационный тест специально просит не менее половины заданий с «вы», чтобы
проверять обращение. Обычный генератор не получает этого искусственного ограничения.
Набор нужно также прочитать вручную: успешное прохождение программных проверок
не доказывает естественность всех фраз.

## Выпуск

Изменения проверены локально и через cloud API; production не изменялся.
Нужен обычный выпуск приложения с новыми промптами. Новая модель задаётся
дефолтом приложения, её можно переопределить через `AI_SENTENCE_MODEL`.
Промпты загружаются из файлов или встроенной копии; при внешних override-файлах
нужно обновить их вместе с кодом, поскольку формат `issues` расширился.

Миграция БД не нужна. Новая генерация действует на будущие наборы. Существующие
попытки и их оценки не пересчитываются. Для ещё не выполненных старых заданий
новая проверка принимает допустимые варианты, если старый контекст не определяет
единственный выбор. Полноценный browser/DB/production smoke не выполнялся.
