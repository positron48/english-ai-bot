# План развития / идеи улучшений

Документ описывает возможные направления развития проекта English Bot (Telegram-бот + веб-приложение для изучения английского с SRS и AI).

---

## Текущее состояние (кратко)

- **Telegram-бот**: команды, запрос слов, напоминания о тренировках (nudge).
- **Веб-приложение (Vue 3)**: словарь с mastering score (красный–зелёный), наборы слов, грамматика (курс из сабмодуля), тренировки SRS (в т.ч. spell/type по порогу), AI-чат, настройки, админка (stats, circuit breaker, prompt tester, word sets, db-schema).
- **Бэкенд (Go)**: Postgres, SM-2, training worker (LLM-генерация карточек), circuit breaker, JWT + OTP, rate limiting.
- **Грамматика**: разделы/главы/тесты, placement test, попытки; курс в read-only сабмодуле.

---

## 10 идей для развития / улучшения

### 1. Mastering score в БД и дневное обновление

Сейчас score считается в запросе словаря. В `todo.md` уже есть задача: писать mastering score в слово (например, в `user_word_knowledge` или отдельную таблицу по user+word) и обновлять раз в сутки воркером. Это ускорит список словаря и позволит сортировать/фильтровать по «выученности» без тяжёлой агрегации.

### 2. Умный тест по главе грамматики

В `courses/english-grammar/README.md` предложено: стратификация по `theory_block_id`, исключение последних N вопросов по истории пользователя, при двух ошибках подряд в одном блоке — увеличивать долю вопросов по этому блоку. Реализовать это в `grammar_service` и во фронте при формировании теста по главе.

### 3. Экспорт словаря и статистики

В админке и для пользователя: экспорт словаря (слово, перевод, примеры, mastering score) и сводки по тренировкам (даты, количество повторений, due) в CSV. Опционально — экспорт в формате Anki (CSV для импорта в Anki).

### 4. Произношение слов (TTS)

В словаре и в карточке тренировки показывать кнопку «произнести»: один запрос к TTS API (например, OpenRouter/другой провайдер с TTS или бесплатный внешний API) по `display_word`/lemma, кэш по слову, воспроизведение в браузере. Уже есть `useAudio` — можно встроить воспроизведение туда.

### 5. Улучшение напоминаний о тренировках

Помимо «N карточек к повторению»: учитывать streak (дни подряд), в сообщении писать «Ты уже X дней подряд повторяешь» или «Вчера пропустил — сегодня 50 карточек». Опционально — еженедельный дайджест (сколько слов выучено, сколько повторений, streak) в настраиваемый день/время.

### 6. Режим «слабые слова» в тренировках

Фильтр очереди: показывать в приоритете слова с низким mastering score или с недавними ошибками (по `review_events`). Настройка в настройках тренировки: «чаще показывать слабые» (вкл/выкл и, при желании, порог).

### 7. История и контекст в AI-чате

Сейчас чат, скорее всего, по одному сообщению. Добавить хранение последних N сообщений (в БД или в сессии) и передавать их в LLM как контекст, чтобы был диалог и преподаватель мог ссылаться на предыдущие реплики (коррекции, темы).

### 8. Дашборд прогресса и простые графики

На дашборде: график «повторений по дням» за 7/30 дней, рост количества слов в состоянии «mastered», текущий streak. Данные уже есть в `review_events`, `training_sessions`, mastering — нужно агрегировать и отдать API + нарисовать график (например, Chart.js или аналог) во фронте.

### 9. Тренировка прямо в Telegram

Сейчас тренировка только в Web App. Добавить минимальный режим в боте: бот присылает карточку (вопрос + 4 варианта инлайн-кнопками), пользователь жмёт — бот обновляет SRS и присылает следующую. Ограничение: например, до 10 карточек за сессию в боте, «продолжить в приложении» — ссылка на веб.

### 10. Метрики и наблюдаемость

В `go.sum` уже есть OpenTelemetry. Вынести метрики (количество запросов к LLM, длительность ответа, ошибки circuit breaker, кол-во активных пользователей/тренировок в день) в Prometheus-совместимый endpoint или OTLP. Это поможет смотреть на нагрузку и сбои после деплоя (в т.ч. на k3s).
